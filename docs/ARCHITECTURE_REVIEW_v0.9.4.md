# WHISKAY — Architecture, Configuration & Data-Safety Review

**Reviewed source:** user-uploaded `wbself.zip` (v0.9.3 source)  
**Corrected release:** v0.9.4  
**Review date:** 2026-11-06

## Executive finding

The Instagram session path was not changed by the uploaded v0.9.3 configuration. The source still points to `./auth_ig/instagrapi-session.json`, resolved from the project root. The uploaded v0.9.3 test suite, however, used the configured live session path as test data and removed it during cleanup. If `npm test` ran against the active project, that test could delete the real Instagram session. This is the strongest source-supported explanation for the missing session; the exact historical command sequence on the user's device cannot be proven from the ZIP alone.

The same test suite also targeted production statistics, order/ledger JSON, and SQLite queue files. This made `npm test` unsafe on an active installation until test storage was isolated.

## 1. Configuration boundaries

| Location | Purpose | Examples |
|---|---|---|
| `.env` | Secret values only | `IG_PASSWORD`, optional `PROMOTION_PROVIDER_API_KEY` |
| `config/app.json` | Ordinary runtime configuration | WhatsApp owner/pairing number, Instagram username, executable/path settings, command and queue configuration |
| `config/app.example.json` | Safe template | Blank phone/username and default paths |
| `IG_USERNAME`, `IG_SESSION_FILE` | Child-process bridge variables | Generated by Node from `config/app.json`; do not duplicate in `.env` |

`instagram.authMode` is obsolete and is now rejected by config validation. `REDIS_PASSWORD` is unused because the queue is SQLite-backed. Legacy `WA_PAIRING_NUMBER`, `WA_SESSION_DIR`, `WA_SYNC_FULL_HISTORY`, `LID_MAP_FILE`, and `LOG_LEVEL` environment overrides are not the active configuration source; use `config/app.json`. `npm run validate` warns when these old variables remain in `.env`.

Relative configuration paths are anchored to the project root. The configured Instagram session remains `auth_ig/instagrapi-session.json`, separate from WhatsApp Baileys state in `session/self/`.

## 2. Proven v0.9.3 data-loss risks

- `test/instagram-stats.test.mjs` removed `config.instagram.sessionFile` and `config.instagram.statsFile` before/after tests.
- `test/order-engine.test.mjs` removed `config.growth.databaseFile`, which stores growth order/campaign/credit/ledger data.
- `test/sqlite-queue.test.mjs` removed the configured SQLite queue file and WAL/SHM sidecars.

These files therefore needed test-specific paths, not production configuration paths. v0.9.4 redirects all private-state configuration paths to per-test-worker temporary storage whenever Node Test Runner is active. The temporary directory is removed on process exit. Destructive test modules also refuse direct execution outside Node Test Runner.

## 3. v0.9.4 corrections

- Project-root path resolution for relative configuration values.
- Test isolation for WhatsApp session, Instagram session, Instagram statistics, safety guard, LID map, growth ledger, and SQLite queue.
- Regression tests for state-path isolation, obsolete `instagram.authMode`, login refusal when a session path exists, and Instagram status classification.
- Accurate Instagram setup statuses: `USERNAME_MISSING`, `PYTHON_UNAVAILABLE`, `INSTAGRAPI_UNAVAILABLE`, `SESSION_MISSING`, `SESSION_FILE_UNSAFE`, `SESSION_PERMISSION_UNSAFE`, and `SESSION_PRESENT_UNVERIFIED`.
- `SESSION_PRESENT_UNVERIFIED` is local file/permission validation only; it does not claim server authentication.
- Instagram settings and statistics are stored atomically. Login validates profile data before writing the final session file.
- `.iglogin` refuses an existing session path; profile/sync never fall back to password login.
- The startup launcher sends `IG_PASSWORD` only to the bot when the session path does not exist. The worker never receives it. The bot removes it from its environment after one login attempt.
- Relative-path resolution, status reporting, stale environment warnings, provider metadata filtering, and duplicate Instagram statistics plugin cleanup.
- A safe upgrade script makes a full backup and does not overwrite `.env`, `config/app.json`, `session/`, `auth_ig/`, or `data/`.
- README, changelog, QA report, architecture, security, configuration, adapter, release, and upgrade documentation updated.

## 4. WhatsApp and Instagram state separation

`session/self/session-*.json` are Baileys multi-file authentication records. They are not instagrapi settings and must never be copied into `auth_ig/`. The uploaded archive did not contain `auth_ig/instagrapi-session.json`, so this review cannot recover the user's missing Instagram session from the source archive.

## 6. Credential handling note

The uploaded input ZIP included a real `.env` file with assignments for `IG_PASSWORD` and `PROMOTION_PROVIDER_API_KEY`, as well as an obsolete `REDIS_PASSWORD` entry. Their values are intentionally not reproduced here and are excluded from the v0.9.4 release archive. If those credentials were active, rotate the Instagram password and provider API key; remove the unused Redis variable. The uploaded `config/app.json` also contained personalized WhatsApp/Instagram configuration, and is excluded from the release ZIP.

## 7. Operating limits

This release does not promise zero Instagram restrictions. It uses explicit first login, saved-session reuse, local cooldowns, a persistent safety hold, and read-only profile operations. Stop and verify the account through the official Instagram application when a checkpoint, challenge, rate limit, or authentication failure occurs. Do not bypass platform challenges or repeat login attempts.
